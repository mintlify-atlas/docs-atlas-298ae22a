Alto brings all of your cloud storage into a single, cohesive desktop experience. Built on Electron with a fully native GTK4/Adwaita UI — rendered through the gtk-js React component library — Alto looks and feels right at home on modern Linux desktops while remaining cross-platform at its core. Whether you manage a personal Google Drive, a team Nextcloud server, or a mix of several providers, Alto gives you one consistent place to configure remotes, define sync directories, and track the status of every file.

<Note>
  Alto is currently in **active development**. The interface is a fully interactive UI mock — remote management, directory configuration, and status indicators are all wired up in the UI, but the underlying sync backend is not yet implemented. File transfers to cloud providers are not yet functional.
</Note>

## What is Alto?

Alto is a port of [Celeste](https://github.com/hwittenborn/celeste), the original Rust/GTK4/Libadwaita file sync client, rebuilt for Electron and React. The port targets a full 1-to-1 UI replica of Celeste, driven by the gtk-js React component library that exposes native GTK4 and Adwaita widgets. This combination gives Alto the visual fidelity of a native Linux application while supporting macOS and Windows through Electron.

At its core, Alto is a **multi-remote sync manager**. You register one or more cloud remotes in the sidebar, assign local directories to each remote, and Alto will keep them in sync once the backend is complete. Each sync directory has a live status indicator so you can see at a glance whether a directory is fully synced, currently syncing, checking for changes, in an error state, or disconnected.

## Supported Providers

Alto is designed to support a broad range of cloud storage providers. The login dialog lets you pick your provider, enter the required credentials, and have a new remote ready in seconds.

| Provider | Auth Method | Notes |
|---|---|---|
| Google Drive | OAuth | Name-only setup; auth handled via OAuth flow |
| Dropbox | OAuth | Name-only setup; auth handled via OAuth flow |
| Nextcloud | Username & Password | Requires server URL |
| OwnCloud | Username & Password | Requires server URL |
| pCloud | OAuth | Name-only setup; auth handled via OAuth flow |
| Proton Drive | Username & Password | Supports optional TOTP |
| WebDAV | Username & Password | Requires server URL |

<Note>
  The login dialog currently supports **Google Drive** only. Support for the remaining providers listed above is planned for upcoming development iterations.
</Note>

## Architecture

Alto's renderer process is a React application that communicates with the Electron main process over typed IPC channels. Window management operations — close, minimize, toggle maximized, and set decoration insets — are all handled through these typed channels, keeping the GTK4 UI layer cleanly decoupled from Electron's native APIs. For more detail, see the [IPC System](/contributing/ipc-system) and [Architecture](/contributing/architecture) guides.

The build pipeline uses Electron Forge with a Vite plugin, packaging the app as an ASAR archive with hardened Electron Fuses enabled at package time — cookie encryption on, `RunAsNode` disabled, Node.js CLI inspect flags blocked, and embedded ASAR integrity validation enforced.
