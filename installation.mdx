Alto is packaged with [Electron Forge](https://www.electronforge.io/) and distributed in several formats to cover every major desktop platform. Linux users can install via a `.deb` or `.rpm` package; macOS users receive a `.zip` archive; and Windows users get an installer generated by Squirrel. If you prefer to stay on the bleeding edge — or want to contribute — you can also build Alto directly from source.

## Available Package Formats

Electron Forge produces the following output formats when you run `npm run make`:

| Platform | Format | Maker |
|---|---|---|
| Linux | `.deb` (Debian/Ubuntu) | `@electron-forge/maker-deb` |
| Linux | `.rpm` (Fedora/RHEL) | `@electron-forge/maker-rpm` |
| macOS | `.zip` archive | `@electron-forge/maker-zip` |
| Windows | Squirrel installer | `@electron-forge/maker-squirrel` |

<Tip>
  Linux users should prefer the `.deb` or `.rpm` package for their distribution — these formats integrate with your system package manager, making updates and uninstallation straightforward.
</Tip>

## Build from Source

Building Alto from source requires Node.js and npm. The full build takes just four steps.

<Note>
  Alto requires **Node.js** and **npm** to be installed on your system before you begin. Visit [nodejs.org](https://nodejs.org) to download the current LTS release for your platform.
</Note>

<Steps>
  <Step title="Clone the repository">
    Clone the Alto repository from GitHub and enter the project directory.

    <CodeGroup>
      ```bash npm
      git clone https://github.com/hwittenborn/alto.git
      cd alto
      ```
    </CodeGroup>
  </Step>

  <Step title="Install dependencies">
    Install all Node.js dependencies, including the Electron Forge CLI and the gtk-js packages that power the native GTK4/Adwaita UI.

    <CodeGroup>
      ```bash npm
      npm install
      ```
    </CodeGroup>

    npm creates symlinks in `node_modules/@gtk-js/*` pointing to the locally-linked gtk-js packages declared in `package.json` with the `file:` protocol.
  </Step>

  <Step title="Start the development server">
    Launch Alto in development mode. Electron Forge starts the Vite dev server for the renderer process and opens the Electron window.

    <CodeGroup>
      ```bash npm
      npm start
      ```
    </CodeGroup>

    The dev server uses Vite HMR for the renderer (React) layer. Note that changes to symlinked gtk-js built output may not be picked up by HMR automatically — if you are modifying gtk-js components, restart the dev server after rebuilding the gtk-js packages.
  </Step>

  <Step title="Package for distribution">
    When you are ready to produce distributable artifacts, run the `make` command. Electron Forge bundles the app into an ASAR archive, applies Electron Fuses, and then invokes each configured maker for your current platform.

    <CodeGroup>
      ```bash npm
      npm run make
      ```
    </CodeGroup>

    Output files are written to the `out/make/` directory. On Linux you will find `.deb` and `.rpm` packages; on macOS a `.zip`; on Windows a Squirrel installer.
  </Step>
</Steps>

## What the Build Pipeline Does

Alto's Electron Forge configuration (`forge.config.ts`) defines the full packaging pipeline:

- **Vite plugin** — Builds the main process entry (`src/main.ts`), the preload script (`src/preload.ts`), and the renderer (`main_window`) all in one pass.
- **ASAR packaging** — The entire app is packed into an ASAR archive (`packagerConfig.asar: true`), which improves load times and enables integrity validation.
- **Electron Fuses** — Applied at package time to harden the binary: `RunAsNode` is disabled, cookie encryption is on, `NODE_OPTIONS` and `--inspect` flags are blocked, and embedded ASAR integrity validation is enforced. The app will only load code from its ASAR archive.
- **Makers** — Each maker runs on its target platform only; cross-compilation is not configured by default.

## Rebuilding gtk-js (Development Only)

Alto's UI is powered by the [gtk-js](https://github.com/hwittenborn/gtk-js) React component library. During development, these packages are consumed from local file paths rather than the npm registry. If you make changes to gtk-js, rebuild its packages before restarting Alto:

```bash
cd ../../gtk-js/gtk-js && bun run build:packages
```

Then restart Alto's dev server with `npm start`. Vite HMR may not detect changes to symlinked built output, so a full restart is required.
