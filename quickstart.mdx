From first launch to an actively syncing remote, Alto is designed to get out of your way as quickly as possible. This guide walks you through every step of the initial setup — opening the app, adding a cloud remote, configuring a sync directory, and understanding the live status indicators that tell you what Alto is doing at any moment.

<Note>
  Alto is currently in **active development**. The UI is a fully interactive functional mock with planned sync backend integration. All remote management, directory configuration, and status indicators work in the interface, but actual file synchronisation to cloud providers is not yet wired up.
</Note>

## First-Run Setup

<Steps>
  <Step title="Launch Alto">
    Open Alto from your application launcher or, if you built from source, with `npm start` from the project directory. The main window opens with two panels side by side:

    - **Sidebar (left)** — Lists all configured cloud remotes. Starts empty on first run. The header bar shows an **Add Server** button (`+`) on the left and a menu button on the right.
    - **Content area (right)** — Shows the sync directories and status for whichever remote is selected in the sidebar.

    On narrow screens or small windows, the layout folds into a single panel and you can navigate between the sidebar and content area using the navigation arrows.
  </Step>

  <Step title="Add your first cloud remote">
    Click the **+** (Add Server) button in the sidebar header bar. This opens the **Log In** dialog as a modal overlay.

    In the dialog:
    1. Use the **Server Type** dropdown to pick your cloud provider (e.g. Google Drive, Dropbox, Nextcloud).
    2. Fill in the fields that appear for your chosen provider. Google Drive, Dropbox, and pCloud only ask for a **Name**; Nextcloud, OwnCloud, and WebDAV also ask for a **Server URL**, username, and password; Proton Drive asks for username, password, and an optional TOTP code.
    3. Your remote name must be unique, must not be empty, and may only contain letters, numbers, underscores, hyphens, periods, and spaces. It cannot start with a hyphen or space, and cannot end with a space.
    4. Click **Log In**. The button remains disabled until all validation passes.

    Once confirmed, your new remote appears in the sidebar list.

    For a detailed walkthrough of every provider's login flow, see the [Adding a Remote](/guides/adding-a-remote) guide.
  </Step>

  <Step title="Add a sync directory">
    Select your new remote in the sidebar to open its content panel. The panel shows a list of configured sync directories — empty to start.

    Click **Add Directory** (or the equivalent action in the content header bar) to configure your first sync:

    1. **Local path** — Choose the local folder to sync. Alto uses Electron's native file chooser dialog.
    2. **Remote path** — Set the corresponding path on the cloud remote.
    3. Save the configuration to add the directory to the list.

    You can add multiple sync directories per remote, and each directory is managed independently. For full details on options like file exclusions, see [Sync Directories](/guides/sync-directories).
  </Step>

  <Step title="Monitor sync status">
    Each sync directory row displays a live status indicator. Alto reports one of the following states:

    | Status | Meaning |
    |---|---|
    | **Synced** | The local directory matches the remote — no action needed. |
    | **Checking** | Alto is comparing local and remote file trees to detect changes. |
    | **Syncing** | A sync operation is in progress; files are being transferred. |
    | **Error** | One or more files could not be synced. See step 5. |
    | **Disconnected** | Alto cannot reach the remote (network issue or credential problem). |

    The status updates automatically. You do not need to refresh the view.
  </Step>

  <Step title="Resolve any errors">
    If a directory enters the **Error** state, click on the directory row to drill into the detail view. The detail view shows a breakdown of the individual files that failed, along with the reason for each failure. From here you can:

    - Review the error message and decide how to handle the conflict.
    - Remove a file exclusion or add a new one to work around persistent issues.
    - Dismiss resolved errors once you have addressed the underlying problem.

    For a full guide to the error and conflict resolution workflow, see [Managing Errors](/guides/managing-errors).
  </Step>
</Steps>
